# WaveSense 구현 가능성 문헌 조사

2026-11-19 · 대상: 기밀 공간 방범, ESP32-C5(보드당 안테나 1개), 송신 1 + 수신 6, 웹캠은 학습용

직접 열어 확인한 자료만 넣었다. 확인하지 못한 것은 "미확인"으로 표시했다. 출처 대부분이 arXiv라서 동료 검토 여부를 함께 적었다.

## 결론

전체 시스템은 구현할 수 있다. 다만 기능마다 근거의 수준이 다르다.

- **근거가 충분한 기능:** 존재 감지, 구역 구분, 0/1/2명 이상 인원 구분, 1인 2D 스켈레톤(같은 방 기준)
- **근거가 없는 기능:** 우리가 원하는 의심 행동(팔을 들고 멈춤, 캐비닛 뒤적임, 웅크림)을 직접 구분한 연구
- **설계 방향:** 의심 행동을 스켈레톤 하나로만 판정하지 않는다. "구역 + 스켈레톤 자세 + 머문 시간"을 묶은 규칙으로 판정한다.
- **우리 몫이 될 수 있는 것:** 기존 ESP32 스켈레톤 연구는 모두 같은 세션 안에서 데이터를 나눠 평가했다. 다른 사람·다른 날·다른 배치로 따로 평가하는 것 자체가 우리가 보탤 수 있는 결과다.

## 기능별 판정

| 기능 | 판정 | 핵심 근거 |
|---|---|---|
| 존재 감지(움직임) | 가능 | 사전 검증 벽 너머 약 97% |
| 정지한 사람 감지 | 가능, 조건 있음 | 호흡 기반 약 95%(IEEE JSAC 2015). ESP32 단일 안테나는 위치에 따라 사각지대가 생김(SA-WiSense) |
| 4구역 구분 | 가능 | ESP32-C6 4구역 0.957, 3.5개월 뒤 데이터로 시험(Gad et al.) |
| 인원 0/1/2명 이상 | 가능 | ESP32 4구역, F1 0.89(Chaudhari et al., 동료 검토 전) |
| 인원 0~3명 정확히 | 근거 약함 | 오류가 1명과 2명 사이에 몰림(부분 확인) |
| 동반 출입 | 직접 근거 없음 | 문 통과 인원 계수는 안테나 2개 이상의 위상차가 필요(Wi-Count) |
| 1인 2D 스켈레톤 | 가능(같은 방) | ESP32 3~4대로 PCK@10 63~83%(arXiv 2편) |
| 다른 사람·다른 방 스켈레톤 | 근거 없음(ESP32) | Intel 장비에서는 다른 방으로 가면 크게 나빠짐(MM-Fi, CSIPose) |
| 정지 자세 구분 | 근거 약함 | 단일 안테나 쌍으로 정지 자세 85%, 다른 방에서는 55%(CSIPose) |
| 비슷한 자세끼리 구분 | 약함 | ESP32로 비슷한 자세 7종 0.529(Gad et al.) |
| 2명 이상 동시 행동 | 약함 | 인원이 늘면 활동 인식이 약 26%p 하락(WiMANS) |
| 수신 6대 시간 동기화 | 가능 | 송신 패킷의 시퀀스 번호로 묶음. 위상 동기화는 우리 구성으로 불가 |
| ESP32-C5 5GHz CSI | 가능, 설정 필요 | HT40(서브캐리어 117개), `lltf_bit_mode` 설정 필요 |
| 다른 방 적용 | 큰 하락 | 모든 문헌에서 확인됨. 샘플 몇 개로 보정하는 방식이 대안(FewSense) |

## 1. 스켈레톤 추정

### ESP32 사례

**arXiv 2504.16655** (Cho 외, 2025, 동료 검토 미확인)
- ESP32-S3 송신 1대, 수신 3개, 2.4GHz, 서브캐리어 114개, 300Hz
- 정답은 GoPro 영상에 YOLOv11-Pose를 돌려 만든 2D 관절 17개. 피험자 20명
- 서기·걷기·쪼그리기는 PCK@10 83.4%, 낙상은 28.5%
- 같은 영상을 시간 기준으로 80/20 나눠 평가함. 다른 사람으로 검증하지 않음
- 저자가 밝힌 한계: 빠른 동작과 누운 정지 자세에 약하고, 손·발 추적이 약하며, 가구 배치와 다른 사람의 움직임에 민감함

**PowerSkel, arXiv 2403.01913** (Yin 외, 2024)
- ESP32 4대가 서로 송수신해 경로 12개를 만듦. 높이 1.3m, 30Hz
- 정답은 Kinect V2의 2D 관절 17개. 피험자 6명, 방 1곳
- PCK@10 63.47%, PCK@50 96.27%. 보드를 2대로 줄이면 PCK@10이 3.96%p 떨어짐
- 행동 목록에 "캐비닛 문 조작"이 있어 우리 시나리오와 가장 비슷함
- 다른 사람·다른 방 평가는 없음

### 다른 장비 사례(비교용)

| 연구 | 장비 | 결과 |
|---|---|---|
| WiFlow, arXiv 2602.08661 | Intel 5300, 안테나 3개 | 한 명씩 빼고 학습해 다른 사람으로 시험할 때 PCK@20 87.26% |
| CSIPose, IEEE TMC 2025(동료 검토) | 스마트폰 단일 안테나 쌍 | 정지 자세 85.38%, 움직이는 자세 94.02%(PCS 기준). 다른 방에서 55.36% |
| MM-Fi, NeurIPS 2023 | TP-Link 공유기 | 관절 오차 186.9mm에서 다른 환경으로 가면 367.8mm |
| Person-in-WiFi 3D, CVPR 2024 | 다중 안테나 | 관절 오차 1인 91.7mm, 2인 108.1mm, 3인 125.3mm |
| arXiv 2606.10048 | USRP SDR 3대 | 진폭만 써도 진폭과 위상을 함께 쓸 때와 비슷 |

### 공개 데이터셋

ESP32 CSI와 관절 좌표를 짝지은 공개 데이터셋은 찾지 못했다. 학습 코드는 MM-Fi나 WiFlow(Kaggle 공개)로 먼저 검증한다.

### 설계 시사점

- 보드 여러 대를 분산 배치하는 방향은 문헌과 맞는다. 6대를 두 높이에 두는 구성은 기존 사례보다 공간 다양성이 크다. 다만 높이 효과를 직접 검증한 논문은 없다.
- 정답 라벨의 품질이 정확도의 상한선이다. MediaPipe나 YOLO-Pose의 신뢰도가 낮은 관절은 학습 손실에서 뺀다.
- ESP32는 위상 잡음이 커서 진폭만 쓰는 것이 일반적이다.
- 송수신 보드의 위치를 모델 입력에 넣으면 배치가 바뀌었을 때 오차가 크게 줄었다는 결과가 있다(PerceptAlign, arXiv 2601.12252, MobiCom 2026 채택 여부 미확인).

## 2. 행동 인식과 인원 추정

### 근거

- **Gad et al.** (ESP32-C6, 단일 안테나, 게재처 미확인)
  - 사무실 4종(빈방, 업무, 수면, 식사) 0.942, 4구역 위치 0.957
  - 비슷한 자세 7종(시청, 독서, 식사 등)은 0.529
  - 시험 데이터는 학습 데이터보다 약 3.5개월 뒤에 모음
- **Custance et al., Electronics 2023** (ESP32, 동료 검토): 앉은 자세와 선 자세로 사람을 식별해 착석 약 84%, 기립 약 74%
- **Strohmayer & Kampel, arXiv 2401.00964** (ESP32-S3): 벽이 없는 조건과 벽 너머 조건을 서로 바꾸면 36~65%로 하락. 데이터 증강을 해도 최고 69.6%. 보드 내장 안테나에서는 증강 효과가 거의 없음
- **XAI2CSI, arXiv 2608.31034** (802.11ax, 안테나 4개): 같은 조건 88~98%, 처음 보는 사용자 최대 65%, 처음 보는 환경 28% 이하
- **WiMANS, ECCV 2024** (Intel 5300, 0~5명): 활동 인식 약 61~65%. 5GHz가 2.4GHz보다 대체로 나음
- **Chaudhari et al., Preprints 2026** (ESP32, 동료 검토 전): 4구역, 250시간 이상. 재실 여부 F1 0.96, 0/1/2명 이상 F1 0.89
- **Wi-CaL, IEEE Access 2022** (ESP32): 작은 방 5명 기준 인원 오차 0.35명
- **Wi-Count, ICCCN 2018** (Intel 5300): 문 통과 방향 약 95%, 인원 약 92%. 수신 안테나 2개의 위상차가 필요
- **Chimsang & Khemapatapan, 2026** (ESP32, 태국 지역 학술지): 정상 패턴만 학습해 침입을 감지하는 방식. F1 0.970, 다른 방 두 곳에서 0.933과 0.923

### 정지 감지

- Wu et al., IEEE JSAC 2015: 호흡으로 정지한 사람을 감지. 움직임·정지 모두 약 95%, 빈방 판별 96%
- SA-WiSense, arXiv 2507.17623: ESP32 단일 안테나의 사각지대 문제를 다룸. 8m까지 검출률 91.2%

### 근거가 약한 행동과 바꿀 판정 방식

| 원래 행동 | 문헌 근거 | 바꿀 판정 방식 |
|---|---|---|
| 모니터 앞에서 팔을 들고 멈춤(촬영 의심) | 없음. 팔을 든 채 멈추면 호흡만 보이는 상태와 비슷해질 수 있음 | 모니터 구역 + 손목 높이(스켈레톤) + N초 이상 정지 |
| 캐비닛 앞 뒤적임 | 직접 근거 없음. 가장 가까운 "줍기"가 약 60%대(WiMANS) | 캐비닛 구역 + 상체 숙임 + 작은 움직임이 계속됨 |
| 웅크려 숨기 | 없음 | 칸막이 구역 + 낮은 자세 + 움직임 적음 |
| 서서 대화 대 앉아서 업무 | 약함(0.529) | 구역 정보로 보완 |
| 서성임 | 없음 | 구역 이동 횟수와 머문 시간 규칙 |
| 동반 출입 | 없음 | 출입 카드 기록 후 T초 안에 출입구 구역 인원이 1명에서 2명 이상으로 바뀜 |

인원 목표는 "0~3명 정확히"에서 "0명, 1명, 2명 이상" 3단계로 바꾸는 것이 문헌과 맞다.

## 3. 장비와 동기화

- **시간 동기화:** 송신 보드가 보내는 패킷에 시퀀스 번호를 넣고, 수신 6대의 데이터를 이 번호로 묶는다. USB로 노트북에 도착한 시각은 쓰지 않는다. 웹캠은 같은 노트북 시계로 기록하고 프레임 단위로 맞춘다. MM-Fi는 이 방식으로 동기 오차를 25ms 이내로 맞췄다. LED나 박수 같은 표시를 넣어 오차를 직접 측정한다.
- **위상 동기화:** 보드 간 위상까지 맞추려면 공통 40MHz 클럭과 위상 기준 신호가 필요하다(ESPARGOS, arXiv 2502.09405). 우리 구성으로는 할 수 없으니 진폭만 쓴다.
- **ESP32-C5 5GHz 설정:**
  - HT20, HT40, HE20만 지원하고 80/160MHz는 지원하지 않는다(ESP-IDF 문서).
  - `lltf_bit_mode`를 설정하지 않으면 CSI가 프레임마다 똑같이 나오는 문제가 보고되어 있다(esp-idf issue #18493).
  - CSI 데이터의 첫 4바이트가 무효일 수 있다.
- **USB 대역폭:** esp-csi 예제의 921600 baud는 약 92KB/s다. HT40 데이터를 ASCII로 초당 100번 보내면 보드당 약 110KB/s라 포화된다(직접 계산). 바이너리 출력이나 더 높은 baud를 쓰고, 보드 6대는 전원이 따로 들어가는 USB 허브에 나눠 꽂는다. 시퀀스 번호가 빠진 비율을 기록한다.
- **참고 데이터셋:** IEEE DataPort "ESP32 Multi-Transmitter Wi-Fi CSI Dataset"
  - ESP32-C5 송신 4대, 수신 1대. 송신 보드당 초당 50패킷을 번갈아 보냄
  - 서브캐리어 56개, 피험자 4명, 방 3개, 7.93시간

## 4. 다른 방으로 옮길 때

- 새 방에서 성능이 떨어지는 건 모든 문헌에서 같다.
- FewSense(arXiv 2203.02014): 새 환경에서 샘플 5개만으로 보정해 82.7~96.5%. 수신기 여러 대를 합치면 평균 약 30% 향상됐다.
- 비슷한 연구의 학습 데이터 규모는 피험자 4~40명, 약 8~9시간, 공간 3~4곳이다.

## 5. 보안상 위험

- **Et Tu Alexa?, NDSS 2020:** 벽 밖에서 스마트폰 한 대로 Wi-Fi 패킷을 엿들어 사람 움직임을 감지했다. 방 안 기기 수에 따라 86.8~99.988%. 공유기가 위장 신호를 섞으면 탐지율 47%까지 떨어진다.
- **LeakyBeam, NDSS 2025:** 암호화되지 않은 빔포밍 패킷을 20m 밖에서 수집해 감지했다.
- **IRShield, arXiv 2112.01967:** 신호를 반사하는 특수 표면(IRS)으로 동작 탐지를 5% 이하로 낮췄다.
- 공격자는 패킷을 해독하지 않아도 움직임을 감지할 수 있다. 그래서 암호화만으로는 막을 수 없다. 송신 출력을 최소화하고 채널을 무작위로 바꾸는 대책을 설계에 넣는다.

## 설계에 반영할 것

1. 의심 행동은 "구역 + 스켈레톤 자세 + 머문 시간" 규칙으로 판정한다.
2. 인원 목표를 0명, 1명, 2명 이상 3단계로 바꾼다.
3. 평가는 다른 사람, 다른 날, 가구 배치 변경으로 나눠 보고한다. 가능하면 방 2곳 이상에서 수집한다.
4. 송신 패킷에 시퀀스 번호를 넣고, USB 출력은 바이너리나 높은 baud로 바꾼다.
5. 5GHz는 HT40 고정에 `lltf_bit_mode`를 설정하고, 2.4GHz와 비교한다.
6. 외장 안테나를 검토한다. 보드 내장 안테나에서는 데이터 증강 효과가 거의 없었다는 결과가 있다.
7. 학습 코드는 MM-Fi나 WiFlow 공개 데이터로 먼저 검증한다.

## 아직 모르는 것

- ESP32-C5의 실제 최대 CSI 패킷률과 USB 실효 속도
- 보드 6대를 동시에 쓸 때의 패킷 손실률
- ESP32 스켈레톤의 다른 사람·다른 방 성능(검증된 문헌 없음)
- ESP32-C5(5GHz)로 자세를 추정한 사례(없음)
- 정지한 사람 2명 이상을 세는 ESP32 결과(없음)

열람하지 못해 인용하면 안 되는 자료:
- WiPowerSys
- Burimas et al. 본문
- Wi-Alert, C-Sense, RDFID, Wi-Alarm
- Alzaabi et al.(IEEE Access 2024)의 오차 수치
- Widar3.0 정확도
